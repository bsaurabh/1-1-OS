### Q1 — Claude API Response Delivery: Streaming or Non-Streaming?

Interview questions are generated by Claude Haiku. The manager sees the question appear after submitting their answer. How should the response be delivered?

**A)** Non-streaming — wait for the full Claude response before returning to the client. Simpler implementation (standard `fetch` + JSON response). Latency: ~1–2s per question (Haiku is fast). The submit button shows a spinner during this time.

**B)** Streaming — use Server-Sent Events (SSE) to stream Claude tokens to the client as they are generated. Question text appears word-by-word, like ChatGPT. More complex implementation (requires SSE endpoint + client-side stream reader). Lower perceived latency.

[Answer]: A

---

### Q2 — Claude API Timeout: How long to wait before declaring failure?

If Claude does not respond within a configurable time, the interview falls back to the manual profile edit flow. What should the timeout be?

**A)** 10 seconds — aggressive. Suitable for Haiku which is very fast. Sonnet synthesis may occasionally exceed this on the first call.

**B)** 20 seconds — balanced. Accommodates Haiku comfortably and Sonnet synthesis reliably. Vercel serverless functions allow up to 10s on Hobby; 20s requires Vercel Pro or bumping to `maxDuration`.

**C)** 30 seconds — conservative. Gives Sonnet synthesis maximum headroom. Requires `maxDuration: 30` in the API route config (available on Vercel Hobby via `export const config`).

[Answer]: C

---

### Q3 — Claude API Retry: Automatic retry on failure?

If a Claude call fails (network error, 529 overloaded, 5xx), should the system retry automatically before showing the fallback?

**A)** No retry — fail immediately on any error, return the fallback 503 response. Simplest implementation. Manager sees the fallback message right away.

**B)** Single retry — retry once after a 1-second delay. If the second attempt also fails, return 503. Handles transient errors without long wait times.

**C)** Exponential backoff — retry up to 3 times with 1s, 2s, 4s delays. Maximises Claude availability but adds up to 7s of wait time in the worst case.

[Answer]: B
